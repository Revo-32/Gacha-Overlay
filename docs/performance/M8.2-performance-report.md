# M8.2 Performance / Reliability Profiling Report

## 1. 범위와 판정 원칙

- 측정일: 2026-09-01 (Asia/Seoul)
- 대상: `GachaOverlay.App` Release (`net8.0-windows`)
- 환경: Windows 10.0.26200 x64, .NET SDK 8.0.424, 논리 프로세서 16, 메모리 31.9 GiB
- 절대 CPU/RAM 수치를 범용 합격선으로 사용하지 않았다.
- 실제 Release 관찰, deterministic 자동 검증, 사용자 실환경 필요 항목을 구분한다.
- Discord 메시지 본문, credential, 사용자명 및 사용자별 경로를 보고서에 기록하지 않았다.

## 2. 계측 구현

로컬 프로세스에서만 유지되는 bounded metrics collector를 추가했다. Counter와 gauge는 현재값만, duration은 metric당 최근 256개 표본만 보존하며 average/max/p95/p99를 만든다. Diagnostic ZIP에는 다음 계측을 포함한다.

- Process: uptime, normalized process CPU, Working Set, Private Bytes, Handle/Thread, GC memory/collections, 가능한 경우 GDI/USER object
- RPC: 연결 누적 시간, reconnect/error/event/GET_CHANNEL/GET_CHANNELS/stale discard, event duration
- Chat: 활성 Main 수, normalization/presentation duration, forward/opaque 결과, retention/stale count
- Media: active download, success/failure, decode duration, hit/miss/stale, cache item, decoded byte estimate
- UIA: poll/scan/coalesce/in-progress, duration, node count, Complete/Partial/Unavailable, last complete time
- Sales: active queue/Sold, health, resync/manual resync, coverage, last complete time
- WPF: HUD/Settings update duration, 50 ms 이상 diagnostic long-operation count, coalesced update count

이 수치는 telemetry나 upload에 사용되지 않는다.

## 4. Audit 결과

### Idle / hidden HUD

- HUD presentation은 state event 기반이다. per-frame timer 또는 보이지 않는 HUD 전용 render loop가 없다.
- 위치 저장 timer는 변경 후 debounce 용도이며 dispose 시 Tick handler를 제거한다.
- 게임 foreground fallback timer는 controller dispose 시 제거된다.

### UIA backlog

- UIA는 STA worker 1개가 scan을 동기 실행한다. 다음 scan task를 queue에 계속 추가하는 구조가 아니다.
- 실행 중 explicit resync 50회를 발생시킨 테스트에서 최대 동시 scan은 1, pending scan은 1개로 합쳐졌으며 coalesced counter가 증가했다.
- Sales OFF 후 scan/poll metric과 adapter scan count가 정지하고, 다시 ON에 해당하는 source restart 시 새 scan이 시작되는 것을 검증했다.

### Retry / log storm

- RPC는 bounded exponential reconnect delay를 유지한다.
- UIA unavailable은 2–10초 bounded backoff를 유지하며, 정상 scan summary는 상태 변경 또는 30 scan마다 기록한다.
- opaque hydration은 1회 bounded retry 후 UIA/fallback으로 종료한다.
- 로그 파일은 파일당 2 MiB, 총 5개 rotation으로 제한된다. Discord message body는 기록하지 않는다.

### Media / bitmap

- emoji 64, thumbnail 24, sticker 24 item LRU 상한을 유지한다.
- WPF bitmap은 background decode 후 `Freeze()`된 immutable source만 UI로 전달한다.
- 해상도·decode quality·sticker/emoji 품질 정책은 변경하지 않았다.

## 5. 실제 발견 문제와 수정

### 실패 cooldown key의 무제한 증가 가능성

기존 `BoundedAsyncCache`는 성공 bitmap entry와 in-flight work는 제한했지만, 서로 다른 URL이 계속 실패할 때 `_retryAfter` key 수에는 상한이 없었다.

- Before: 서로 다른 실패 key N개가 cooldown 시간 동안 N개 모두 유지될 수 있음(구조적으로 unbounded).
- Fix: 만료 entry를 먼저 정리하고, 남은 cooldown key를 해당 cache capacity까지 제한한다.
- After: synthetic 5,000 unique failure에서 cache capacity 24, cooldown key 24, cached bitmap 0.
- 정확성 영향: 같은 key의 즉시 retry storm 억제는 유지된다. 오래된 실패 key만 먼저 제거되어 필요 시 정상 재시도가 가능하다.

그 외에는 측정으로 확인된 병목이나 monotonic retained-state 증가가 없어 대규모 cache/UIA/RPC 구조 변경을 하지 않았다.

## 6. 남은 관찰

- 30초 Release 관찰은 장시간 leak 판정 자료가 아니다.
- Scenario A/B/D/E의 실제 UIA p95/p99, media decode p95와 WPF p95는 Sales Live 및 실제 메시지/이미지 활동이 있는 사용자 세션의 Diagnostic ZIP으로 수집해야 한다.
- 실제 sleep/wake, Discord 정상 종료/재실행, 다중 monitor/DPI 이동은 사용자 환경에서 수행해야 한다.
