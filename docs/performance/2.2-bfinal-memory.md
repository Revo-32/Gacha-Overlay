## Decisions

1. **Current-layout outlines — REJECTED for this commit.** In the B0 Mixed allocation
   audit, Point arrays/collections, path geometry and WPF effective-value arrays are
   substantial sampled allocation categories. Source inspection confirmed repeated
   `GlyphRun.BuildGeometry()` on each paint. The new implementation freezes/reuses
   only current TextLine shapes and baseline offsets. It retains no GlyphRuns,
   brushes, old widths or global message cache. Existing content/font/DPI/width/wrap
   invalidation disposes the layout and its shapes; colors/outlines remain live paint.
   This was a newly verified implementation, not an automatic import of C.
   A second variant used exact WPF StreamGeometry curves (no flattening); 45/45 pixels
   remained identical. However, three-run medians did not justify either cache:

   | Mixed | B0 | Current PathGeometry cache | Compact StreamGeometry cache |
   | --- | ---: | ---: | ---: |
   | Private MiB | 182.25 | 187.32 | 185.53 |
   | CPU, one-core % | 46.22 | 45.85 | 44.62 |
   | Allocation MiB/s | 66.860 | 63.146 | 66.318 |
   | Dispatcher p95 ms | 77.380 | 78.119 | 78.508 |

   Compact Chat20 Private was 129.96 vs B0 130.07 MiB; compact SalesMedia was
   154.48 vs B0 150.46 MiB. The fixed repaint microbenchmark did greatly reduce
   allocations (~375 → 11 MiB for 1,200 redraws), but that isolated win did not
   establish an application memory/latency win. Both prototypes and cache-only tests
   were removed from product/commit scope; local captures/source snapshots are retained
   only under ignored artifacts. Final text rendering remains exact B0.
2. **Cached GIF lifecycle — correctness repair.** Four focused tests reproduced B0
   playback loss after hidden enrichment, settings, responsive changes and OFF/ON.
   Live media slots now retain references to already-cached sources separately from
   disposable players; repeated completion does not register a duplicate player.
   Message revision/deletion and cache clear discard slot ownership. No offscreen
   eviction, decoded frame cache, new download path or per-frame BitmapSource allocation.
   Emoji slots address the current message/forward owner plus Emoji ID because settings
   rebuild token VMs. They do not keep updating an obsolete token; repeated occurrences
   share the same per-owner source/player. Removal releases all bindings.
3. **Independent preview ownership — correctness repair.** Two tests reproduced
   failure to close an independent frame on original-message edit/delete. Preview
   ownership now uses MessageId rather than mutable-thumbnail reference equality.
4. **Duplicate state — no broad change.** Main Chat remains bounded to 20; projection
   and VMs already reuse attachment/embed/remote metadata references. Small token-array
   copies preserve representation boundaries; no multi-MiB duplicate owner was proved.
5. **Settings/GTA/resources — no broad change.** SettingsClose typed-heap growth
   includes framework caches and retained page state. No single large accidental
   owner was demonstrated. Settings remains one process with preserved UI state;
   GTA canonical state and independent floating window UX remain unchanged.
