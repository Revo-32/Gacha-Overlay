## 3. User-machine idle soak (필수 후속 실측)

Release EXE에서 다음을 수행한다.

1. Discord 연결, Main 정상, Sales Live, HUD 평소 상태로 둔다.
2. 시작 직후 Settings → 진단 및 복구 → `진단 파일 만들기`로 ZIP을 저장한다.
3. 앱을 4시간 유지하고 두 번째 ZIP을 저장한다.
4. 총 8시간 후 세 번째 ZIP을 저장한다.
5. 세 ZIP의 `runtime-metrics.json`에서 Working Set, Private Bytes, Handles, Threads, GDI/USER, UIA p95/p99, reconnect/error를 비교한다.

Red flags:

- Working Set/Private/Handle/Thread/GDI/USER가 회복 없이 interval마다 계속 증가
- UIA p95/p99가 polling interval을 지속 초과
- reconnect/error/media failure가 활동 없이 지속 증가
- Dispatcher 50 ms+ diagnostic count가 반복 증가

## 5. Discord restart procedure

1. 앱과 Discord가 Connected/Live인지 확인한다.
2. Discord를 정상 종료한다.
3. 앱이 살아 있고 Reconnecting/Disconnected 상태를 표시하는지 확인한다.
4. Discord를 다시 실행한다.
5. Main bootstrap과 Sales resync 복구, duplicate subscription/message/queue 부재를 확인한다.
6. 완료 후 Diagnostic ZIP을 저장한다.

## 6. Sleep / wake procedure

1. Connected/Live 상태에서 Diagnostic ZIP을 저장한다.
2. Windows Sleep 후 몇 분 뒤 Resume한다.
3. HUD, Discord reconnect, Main, Sales, F9/F10, Settings를 확인한다.
4. 새 ZIP에서 old generation stale discard는 허용하되 worker/reconnect/scan 수가 중복 증가하지 않는지 비교한다.
