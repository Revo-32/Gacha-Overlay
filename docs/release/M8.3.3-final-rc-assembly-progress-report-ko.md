## 1. 최종 요약

M8.3.3 보완 작업을 완료했다. 10페이지 빠른 시작과 40페이지 전체 사용자 설명서를 분리했고, 전체 설명서의 App Tester 절차는 일반 흐름에서 제거하여 권한 오류가 계속될 때만 사용하는 조건부 문제 해결 항목으로 정리했다.

README는 제품 소개, 실제 사용 방식, Discord 자체/Legacy 오버레이 및 Bot 기반 도구와의 신중한 구조 비교, M8.2 실측 성능, 보안·데이터 처리와 알려진 제한 사항을 포함하도록 개편했다.

최종 Windows x64 RC는 전체 빌드·테스트·포맷·publish를 다시 수행해 조립했다. ZIP 루트는 EXE, 빠른 시작, 전체 설명서, Licenses의 정확히 네 항목이며 package, fresh extraction, ZIP 구조 검증이 모두 통과했다.

GitHub 저장소 생성, remote push, tag, Draft Release와 asset 업로드는 아직 실행하지 않았다. 사용자의 “commit 전 보고” 요청에 따라 이번 변경은 로컬 working tree에 미커밋 상태로 유지했다.

## 5. README 및 문구 감사

README의 비교는 직접 성능 우위 주장이 아니라 사용 구조와 trade-off만 설명한다.

- Gacha Overlay: 독립 WPF HUD, Discord Desktop Local RPC/IPC, 판매 관찰용 읽기 전용 UI Automation
- Discord 자체/Legacy 오버레이: 내부 구현을 추정하지 않고 Discord가 제공하는 기능이라는 범위로 제한
- Bot 기반 도구: Bot API, 서버 초대·권한·운영이 필요할 수 있고 서버 전체 명령·중재·자동화에 더 적합할 수 있음을 명시
- 직접 비교 benchmark를 수행하지 않았음을 명시
- game DLL injection, game memory read, graphics API hook, Chromium/Electron hook, packet interception을 사용하지 않는다는 현재 source 범위의 사실만 기재
- Bot Token을 요구하지 않지만 개인 Client ID/Secret/OAuth와 로컬 PC 리소스가 필요하다는 trade-off를 함께 기재

M8.2 실측치는 다음 조건과 함께 그대로 사용했다.

- Release / Main Connected / HUD visible / Sales Tracking OFF / 30.35초
- CPU 평균 0.103%
- Working Set 평균 223.81 MiB, 범위 221.70–233.17 MiB
- Private Bytes 평균 147.06 MiB
- Handles 798–865
- Threads 15–27
- 합성 재생: 채팅 5,000건 + 실패 미디어 key 5,000개 + F9/F10 100쌍 / 193.30ms

모든 PC에서 같은 값을 보장하지 않으며 다른 도구와의 직접 비교 결과가 아니라는 단서를 함께 배치했다.

## 12. 알려진 제한 사항

- Discord Local RPC/OAuth는 현재 RC 운용 범위를 기준으로 한다.
- 고정 Production Guild/판매 채널과 선택 가능한 Main Channel 하나를 사용한다.
- 일부 스티커/전달 콘텐츠는 Local RPC 정보 부족으로 `[메시지]` 등으로 일반화될 수 있다.
- 판매 완료 반응 추적은 Discord UI 접근성에 의존한다.
- Discord Desktop이 필요하며 로컬 PC 리소스를 사용한다.
- exclusive fullscreen에서는 HUD가 보이지 않을 수 있다.
- 코드 서명과 자동 업데이트는 제공하지 않는다.
- Long-run Functional Soak는 PASS이나 종료 시점 정량 Diagnostic Snapshot은 수집되지 않았다.
- 8시간 idle, 1–2시간 active, Discord restart, Sleep/Wake 및 다중 DPI/monitor 장기 검증은 별도 사용자 환경 항목이다.
