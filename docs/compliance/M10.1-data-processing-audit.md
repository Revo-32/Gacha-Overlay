기준일: 2026-09-03. 현재 작업 트리(판매완료 전용 후속 수정 포함)를 소스 수준에서 조사했다. 문구 작성 전 수행한 감사이며 법률 검토·인증이나 운영 서버의 전체 설정 감사가 아니다. 실제 사용자 데이터·비밀값은 읽거나 이 문서에 복사하지 않았다.

## 기준 및 범위

- 수정 전 Debug/Release 각각 1,497 PASS, 실패/건너뜀 0. 기존 M10.0 1,486은 역사적 수치다.

- Discord → Railway Backend → 인증된 Remote HTTP/WebSocket → Windows WPF. 로그인은 Web OAuth만 사용한다. 로컬 Discord RPC/UIA/슬래시 페어링은 운영 소스가 아니다.

## 삭제의 실제 한계

- WPF 로그인 해제는 로컬 Remote credential 파일 삭제 + 연결 중단이며 서버 레지스트리를 삭제하지 않는다.
- 서버 인증 레코드는 180일 후 사용할 수 없지만, 주 파일/백업의 물리 보존과 별개다. 같은 설치 재인증 시 기존 주 레코드는 교체되나 이전 backup은 남을 수 있다.
- 서버 삭제 요청 절차는 운영자가 신원을 확인하고 주 파일/백업 및 연결 상태를 함께 다룰 운영 절차가 필요하다. 현재 자동 계정삭제 API/관리 UI는 없다. 새 구현으로 가장하지 않는다.
- 사용자는 앱을 종료하고 자신의 앱 데이터/생성한 ZIP을 지울 수 있다. Discord 원문 삭제는 Discord에서 수행해야 하며 앱 파일 삭제로 Discord 원문은 지워지지 않는다.
- 사용자 정의 media URL은 외부 호스트와 통신할 수 있다. ‘모든 통신이 로컬’ 또는 ‘Discord 외 통신 없음’이라는 예전 설명은 현재 Remote 구조에 맞지 않는다.
