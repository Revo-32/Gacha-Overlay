## 4. Discord 설정 안내 교정

- 사용자가 자신의 Discord Application, Client ID(App ID), Client Secret을 직접 준비한다는 점을 명확히 했다.
- 앱이 OAuth access/refresh token 발급과 보호를 처리한다는 점을 사용자 준비 항목과 분리했다.
- Client ID 안내는 현재 Portal에서 보이는 실제 위치를 기준으로 수정했다.
- 새 Application에서 Client Secret 값이 숨겨져 복사할 수 없는 경우 `Reset Secret`을 한 번 실행해 새 Secret을 발급하고 즉시 복사하도록 조건부로 교정했다.
- 이미 안전하게 보관한 Secret이 있다면 불필요하게 다시 초기화하지 않도록 안내했다.
- Redirect URI, `rpc`, `identify`, `messages.read` 등 오타가 치명적인 값은 검색·복사 가능한 본문 텍스트로 제공했다.
- Discord 공식 OAuth2 문서와 현재 Developer Portal 화면을 함께 대조해 단정적인 오안내를 제거했다.

## 5. 스크린샷 및 시각 교정

- 실제 UI에서 확보하고 마스킹한 기본 스크린샷 25장을 사용했다.
- 설명용 파생 이미지 14장에는 얇은 Cyan 강조선과 번호 badge만 추가했다.
- 사용자 검토 결과에 따라 14개 파생 이미지의 강조 좌표를 실제 입력란·버튼·설정 그룹 위치에 맞춰 전수 조정했다.
- 번호 badge의 크기를 줄이고 숫자를 원 중심에 맞췄다.
- PDF 내부 Workflow 카드의 번호도 글꼴 ascent/descent 기준으로 중앙 정렬했다.
- 실제 UI를 새로 그리거나, 가린 개인정보를 복원하거나, 제품 로고를 변형하지 않았다.
- 기본 및 파생 PNG에서 EXIF, text, ICC 등 불필요한 메타데이터가 남지 않았음을 확인했다.

## 6. HUD 및 Windows 트레이 안내 보강

HUD가 화면에 보이지 않는 사용자를 위해 다음 복구 경로를 추가했다.

`Windows 오른쪽 아래 알림 영역 → 숨겨진 아이콘 표시(^) → Gacha Overlay 아이콘 우클릭 → HUD 표시`

이 안내를 설치 문제 해결, HUD 문제 해결, Quick Reference에 각각 반영했다. 실제 tray 구현과 한국어 리소스를 대조해 다음 메뉴를 정확히 표기했다.

- `HUD 표시/숨기기`
- `HUD 잠금/잠금 해제`
- `설정`
- `Discord 연결 설정`
- `Discord 다시 연결`
- `종료`

트레이 아이콘을 더블클릭해도 HUD 표시 상태가 전환된다는 점을 함께 안내했다.

## 7. 기능 및 문제 해결 설명 보강

- F9 HUD 표시/숨김과 F10 잠금/해제의 차이를 구분했다.
- HUD가 잠겨도 펼쳐진 Queue Detail은 시각적으로 유지되며 입력만 click-through 되는 정책을 비교 설명했다.
- 잠금 해제 후 Queue Detail의 Scroll, Chevron, Button 상호작용이 복구되는 동작을 설명했다.
- Sales Tracking OFF, Queue Empty, UltraCompact, 새 세션에서는 기존 자동 접힘 정책이 유지됨을 명시했다.
- Sticker/Forward 메타데이터가 불완전하면 `[스티커]` 또는 `[메시지]` fallback이 표시될 수 있음을 과도한 단정 없이 설명했다.
- Diagnostic ZIP 생성 위치, 공유 전 확인 항목, 자동 업로드되지 않는다는 점을 추가했다.

## 8. 보안 및 통신 설명

- Client Secret과 OAuth token은 Windows 현재 사용자 범위 DPAPI 보호 대상으로 설명했다.
- User Token, Self-bot 및 브라우저 개발자 도구에서 얻은 token 사용을 금지했다.
- 인증 이후 Discord 실시간 이벤트의 주 통신 경로는 PC 내부 Discord Desktop Local RPC/IPC Named Pipe임을 명시했다.
- 별도 공개 웹 서버나 로컬 HTTP callback listener를 운영하지 않아 외부 노출 지점이 비교적 적다는 장점을 설명했다.
- 최초 OAuth token 교환, 필요한 token refresh, 미디어 다운로드에는 Discord 네트워크 통신이 발생할 수 있으므로 “최초 1회 이후 완전 오프라인” 또는 “절대 안전”이라는 표현은 사용하지 않았다.
- Diagnostic ZIP은 사용자가 직접 생성하고 전송하며 앱이 자동 업로드하지 않는다고 명시했다.
