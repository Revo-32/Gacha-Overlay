## 3. Minimal HUD

MinimalHudMode=true를 기본으로 하고 schema 17 이하 설정을 schema 18로 전환합니다. 창 장식 설정과 Compact/Balanced 채팅 밀도·UltraCompact 반응형 동작은 구분하여 유지합니다.

일반 HUD 설정의 기존 모드 선택은 고급/호환 영역으로 이동했습니다. F9 표시/숨김, F10 잠금/해제, 기존 게임 전면 표시 정책은 유지합니다. 잠금 해제 때만 얇은 편집 테두리·이동 바·톱니바퀴가 보이고, 잠기면 편집 표시가 사라집니다.

## 4. Session Badge

- 설정 이름: Host1=DE-SSANTA, Host2=-TheFirstStar-. 저장값과 Backend 슬롯은 기존 Host1/Host2입니다.
- 선택한 한 호스트만 표시하며 다른 온라인 호스트로 자동 대체하지 않습니다.

## 5. Chat Scroll UX

FollowingLatest / ReadingHistory를 분리했습니다. 과거 메시지를 읽을 때 새 메시지가 와도 강제로 아래로 이동하지 않습니다. 기존 recent20 범위 안에서 보이는 메시지 ID와 위치를 기준으로 읽던 위치를 보존합니다.

신규 Add만 미확인 수에 포함하며 최대 20으로 제한합니다. 잠금 해제 + 과거 읽기 + 신규 메시지 조건에서 하단 중앙에 ↓ N이 나타납니다. 버튼을 누르거나 직접 맨 아래로 이동하면 읽기 상태와 숫자가 초기화됩니다.

투명한 빈 공간도 휠 입력을 받습니다. 잠긴 상태에서는 버튼이 숨겨지고 입력은 통과합니다. 수신·미디어 변화 자체는 사용자 스크롤 의도로 간주하지 않습니다.

## 7. Quick Discord Focus

GTA5_Enhanced가 실제 전면 프로세스인 경우에만 modifier 없는 T를 처리합니다. 첫 key-down에 한 번 활성화를 요청하고 반복 key-down과 key-up까지 소비하여 Discord로 t가 새어 들어가지 않게 합니다.

Ctrl/Shift/Alt/Win 조합, 다른 앱에서의 T, 주입된 키는 처리하지 않습니다. 이미 실행 중인 Discord의 최상위 창을 찾아 최소화 복원·활성화만 요청합니다.

Discord 자동 실행, 마우스 이동, 창 배치 변경, 채널 이동, 입력창 포커스/입력, UIA는 추가하지 않았습니다. Windows가 전면 전환을 거절하는 경우 강제 입력으로 우회하지 않습니다. 실제 전환 성공은 게임 환경에서 확인해야 합니다. [Microsoft의 전면 창 정책](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)

## 8. Health / Error UX

정상 상태의 Live/RemotePrimary/Complete 같은 기술 상태는 HUD에서 숨깁니다. 채팅 오류·재연결·로그인 필요·채널 선택 필요는 짧은 사용자 문구로 보여 줍니다. 판매 오류 문구도 EN/KO/JA로 정리했습니다.

정상 빈 판매 목록과 표시할 내용이 없는 선택적 채팅 표면은 접습니다. 장애는 정상으로 위장하지 않으며 자세한 상태는 설정/진단에서 확인합니다.

## 9. Sales Normalization

Core의 하나의 SalesPostNormalizer가 운영 판매글의 텍스트와 이모지를 함께 해석합니다. 새 상품 ID를 별도로 만들지 않고 기존 catalog의 canonical ID와 이모지를 재사용합니다.

- 벙커/붕키/봉카/붕 → 벙커.
- 나클/나클만/나끌/낙글/낙굴/나/낙 → 나클.
- 대창, 1~5대창 → 스패 x1~x5.
- 격납고/항스패 → 항스패.
- 벙나 → 벙커·나클, 벙나항 → 벙커·나클·항스패.
- 엘 → 엘. 짧은 별칭은 일반 문장 내부를 잘못 잡지 않도록 경계를 확인합니다.
- 여러 수량은 스패에만 허용합니다. 다른 상품은 같은 canonical ID를 중복 제거하여 x1로 표시합니다.
- 수량 custom emoji는 제공된 x2~x5 ID가 우선입니다. 이름만으로 추측하는 것은 ID가 없는 경우로 제한합니다. Unicode 1️⃣~5️⃣도 처리합니다.
- 텍스트/이모지 혼합은 등장 순서를 유지합니다.
- 6/7/10대창이나 5대창+x3 같은 충돌은 추측하지 않습니다. 신뢰할 수 있는 다른 상품은 유지합니다.
- Parsed / PartiallyParsed / Ambiguous / Unknown을 구분하고, 편집 시 분류와 상세 원문도 함께 갱신합니다.

## 10. Sales Presentation

[index] [seller] [item · item] 한 줄 상품 행을 유지했습니다. 상품 칩·카드·소스별 별도 행 렌더러는 만들지 않았습니다. 긴 판매자 이름은 상품과 겹치지 않도록 폭을 제한합니다.

신뢰할 수 있는 상품이 없으면 “상세 확인”을 사용합니다. 불명확한 원문과 상대 시간은 펼친 Queue Detail에만 표시합니다. 원문은 최대 4,096자로 제한하고 일반 JSON 직렬화에서 제외합니다. 상대 시간은 분 단위로 갱신하며 본인·다음 본인·현재 본인 행만 기존 테마 색으로 은은하게 강조합니다.

## 11. Completed Sales UX

판매완료 요청만으로 즉시 행을 지우지 않습니다. pending 동안 유지하며 공식 상태 read-back으로 Sold가 확인되면 active queue에서 제외합니다. 실패하면 행을 유지합니다.

확인된 완료 행에는 약 200ms의 비차단 fade/collapse를 적용하고 끝나면 표시 객체를 제거합니다. 예전 완료된 본인 글의 관리용 행은 active queue에 남기지 않습니다. Sold와 Deleted의 내부 의미, 사람 Reaction 보호, 기존 상태 변경 권한은 유지합니다.

초기 버튼 순서는 판협중 → 판매중 → 판매완료 → 봇 상태 지우기였습니다. 이후 서버에서 판매중/판협중 이모지가 삭제된 것을 사용자가 확인했고, 후속 요청에 따라 일반 판매 바의 판매완료 버튼 하나로 통합했습니다. 상세 목록에는 상태 버튼을 두지 않습니다.

## 12. Authentication UX

기존 Web OAuth만 사용합니다. 별도 로그인 사이트 없이 공식 Discord 페이지로 연결하며, 유효한 기존 보호 자격 증명은 계속 재사용합니다.

운영 기본 주소 https://overlay.revo32.cloud 는 일반 온보딩의 필수 입력 항목이 아닙니다. 수동 주소 변경은 개발자/고급 설정에 남겼습니다. 인증 endpoint, token 저장, DPAPI, 서버 권한 검사는 변경하지 않았습니다.

## 13. Settings

이전/다음 채널 단축키, T Discord 전환 토글, 실제 호스트 표시 이름을 반영했습니다. 일반 화면의 개발 단계 배지를 제거하고 수동 endpoint와 기존 HUD 모드 선택을 고급 영역으로 이동했습니다.

언어·테마·폰트·불투명도·판매/알림 등 기존 설정 구성은 유지했습니다. 설정창 전체 재설계는 수행하지 않았으며 간격·스크롤 길이·적용 버튼 위치는 실사용 후 검토합니다.

## 14. Performance / Lifetime

메시지·잠금·채널·판매 변경은 기존 이벤트 흐름을 사용합니다. 새로운 Backend/Bot 연결이나 네트워크 polling은 추가하지 않았습니다.

- Chat scroll state는 메시지 객체를 별도로 보유하지 않습니다.
- 원문 파서는 4,096자와 최대 128개 structured emoji로 작업량을 제한합니다.
- 기존 최신 30개 판매 source window 정책을 유지합니다.
- 상대 시간은 상세 영역이 보일 때 한 개의 분 단위 타이머를 사용합니다.
- 완료 전환은 한 개의 짧은 타이머로 관리하고 unload/새 갱신 때 정리합니다.
- T 훅은 GlobalHotkeyService가 소유하는 전용 스레드에만 설치하며 Dispose 때 해제합니다. UI dispatcher는 종료하지 않습니다.
- 스크롤 예약, 전환 애니메이션, view 구독, 행 애니메이션의 unload 정리를 검사했습니다.

M9.12 관련 회귀 검사가 통과했습니다. 이것을 다시간 메모리 누수 검증 PASS로 해석하지 않습니다.

## 15. Regression Safety

기존 Chat recent20·전달 메시지·언급·미디어, Sales·Presence·write-back·사람 Reaction 보호, OAuth·DPAPI·진단 비밀정보 제거, 테마 관련 자동 검사를 유지했습니다.

초기 회귀 검사에서 발견한 구정책 기대값은 이번 승인된 정책에만 맞춰 갱신했습니다. WPF 완료 애니메이션의 frozen transform 예외와 판매글 편집 후 상세 정보 갱신 누락은 인도 전에 수정하고 재검증했습니다.

Local RPC·UIA·legacy OAuth·slash pairing을 되살리지 않았습니다. Guild Members intent·Manage Messages 등 추가 권한을 요구하지 않습니다.
