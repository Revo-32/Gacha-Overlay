# M9.7 Sales interaction / reaction write-back

## Scope

M9.7 adds one constrained Discord write capability: an authenticated Remote user may set the status of their own message in the configured Sales channel. It does not add message send, edit, delete, moderation, or a generic reaction endpoint.

## Production status contract

| Domain status | Discord custom emoji | ID |
| --- | --- | ---: |
| Selling | `SELL_onsale` | `1523085309443571762` |
| Negotiating | `SELL_working` | `1524773310288756869` |
| Completed | `SOLD` | `1451583544295034940` |

`closed` (`1418284521337651321`) remains authoritative completion evidence but is not Bot-managed. The three Bot-managed markers are mutually exclusive. A Set adds the desired Bot reaction before removing the Bot's other approved markers. Clear removes only those three Bot-owned reactions.

Any human-added reaction remains untouched, including a manually added reaction from the authenticated user. Humans remove human reactions in Discord. The Bot never enumerates reaction users and never uses a generic clear-reaction operation.

## Authorization and least privilege

The backend derives Guild and Sales channel from trusted configuration. It uses the existing bounded two-minute authorization lease, refreshes Discord authorization when that lease expires, stores the Bot's reaction-capable channel set in the same lease, fetches the canonical message, and compares immutable `AuthorId` with the authenticated Discord user ID. A stale Sales generation, missing message, wrong owner, revoked access, or unavailable verification is rejected before mutation.

Required channel permissions are limited to:

- View Channel
- Read Message History
- Add Reactions

Removing the Bot's own reaction uses Discord's `@me` reaction route through Discord.Net. M9.7 does not require or request Administrator or Manage Messages.

## API and mutation flow

`POST /api/v1/sales/status` accepts only protocol version, message ID, desired high-level status, client request ID, and the active Sales generation. It accepts no Guild, channel, emoji ID, or emoji name.

`RemoteSalesActionService` provides:

- 64 bounded serialization stripes for same-message single flight;
- a 256-entry recent request dedupe cache;
- a 256-entry latest-request version map;
- an eight-actions-per-user-per-minute rate limit;
- deterministic Set semantics and no-op detection;
- typed, redacted result categories.

The action hot path does not perform duplicate full-Guild permission fetches. A valid authorization lease is reused, and the Discord Gateway channel cache is consulted before a REST channel lookup. Canonical message lookup, mutation, and official read-back remain network-bound by design.

After a mutation, the service requests one canonical refresh. Gateway reaction events use the existing coalesced canonical refresh path. The response is never used as Sales domain evidence.

## Read-after-write and UI

`SalesCompletionObservation` carries Discord's canonical aggregate SOLD/closed evidence plus the Bot-owned flags reported by `ReactionMetadata.IsMe`. The WPF UI shows controls only on the authenticated user's owned detail rows while RemotePrimary is Live, tracking is enabled, official evidence is complete, and the HUD is unlocked.

The UI shows pending without changing `SalesStateEngine`. Pending clears only when official evidence matches the requested Bot state. Failure or a bounded ten-second confirmation timeout restores a usable control state. A Bot-completed self message remains as a status-management detail row even after it leaves the active queue, allowing the Bot-owned SOLD marker to be cleared. Human completion markers remain and can keep the domain Sold.

## Preserved invariants

- `SOLD OR closed => Sold` is unchanged.
- Only complete canonical absence can reopen Sold to Pending.
- Delete, queue ordering, and Personal Alert behavior remain owned by `SalesStateEngine`.
- Remote Sales remains primary; UIA and Local RPC remain fallback/read paths only.
- No second Gateway, polling loop, database, broker, or persisted mutation transaction was added.
- Public `1.0.0-rc.1` artifacts are unchanged.
