# M8.0 Release Architecture Audit 완료 보고

## 1. 요약

Gacha Overlay `1.0.0-rc.1` Controlled / Small-group Test Release를 대상으로 M8.0 아키텍처 감사를 완료했다. M7.5 Feature Freeze와 Visual Freeze를 유지했으며 신규 사용자 기능이나 UI 변경은 하지 않았다.

감사 중 MainChat 생성 시각 불변성, 비동기 hydration 최종 commit의 TOCTOU, Forward resolver의 RPC generation 격리, settings crash-safe 저장·복구, 중앙 로그 redaction, Core의 raw UIA 개념 의존에서 실제 미충족 사항을 확인해 최소 범위로 교정했다. 기준선 999개 테스트를 모두 유지하면서 직접 회귀 테스트를 추가해 최종 Debug/Release 각각 1,030개가 통과했다.

## 3. Correctness Fixes

- UPDATE payload의 timestamp가 최초 `CreatedAt`을 바꾸며 MainChat 순서를 이동시키던 가능성을 제거했다.
- Forward/Opaque 비동기 작업이 유효성 검사 직후 DELETE/UPDATE와 경합해 stale 결과를 commit할 수 있던 TOCTOU를 제거했다.
- 같은 source lookup이 reconnect 전후 세대에서 합쳐지거나 이전 결과가 현 세대 캐시에 남는 경로를 generation-scoped로 교정했다.
- settings 저장을 직접 overwrite하지 않는 atomic replace 방식으로 바꾸고 backup 복구를 추가했다.
- raw UIA implementation model을 Core에서 App 경계로 이동했다.
- logger caller의 주의에 의존하지 않도록 최종 파일 출력 경계에 중앙 redaction을 적용했다.

## 4. Async / Message Integrity

MainChat은 `DiscordMessageId`를 identity로 사용하고 `CreatedAt`, Snowflake/MessageId 순으로 정렬한다. UPDATE는 동일 identity를 patch하지만 생성 시각과 retention 위치를 바꾸지 않으며 DELETE는 정확히 한 MessageId만 제거한다.

CancellationToken은 중단 요청으로만 취급한다. 최종 mutation 권한은 generation, message registration/revision, source identity, store membership을 lock 안에서 다시 확인한 commit guard가 가진다. DELETE, UPDATE, retention eviction, reconnect 이후의 늦은 Forward/Opaque completion을 직접 검증했다. 기존 media presentation revision 체계는 유지해 중복 stamp framework를 만들지 않았다.

## 5. Sales Trust / UIA Boundary

UIA는 read-only evidence/fallback sensor로 유지된다. raw AutomationId/ControlType/window 탐색 모델은 App에 있으며 Core는 normalized observation/evidence만 받는다. Sold + NotObserved는 Sold를 유지하고, 완전하고 신뢰된 NotSold만 Pending 복귀를 허용한다. Partial scan은 Pending을 유지하고 positive NotSold evidence를 만들지 않는다. Sales/UIA 장애는 trusted queue를 삭제하거나 Main Chat을 Error로 올리지 않는다.

## 6. Persistence / Security

Settings schema 10과 catalog schema/version 2를 유지했다. Settings는 unique temp file에 serialize한 뒤 디스크 flush, 역직렬화 검증, atomic replace를 수행하고 정상 이전본 하나를 `.bak`으로 보존한다. primary 손상 시 backup, 이후 safe defaults 순으로 복구한다. Product override의 기존 atomic sparse override 구조는 유지하고 failure/backup 회귀 테스트로 고정했다.

로그 출력 경계는 Client Secret, Access Token, Refresh Token, Authorization/Bearer, credential/secret 유사 필드 및 예외 문자열을 redaction한다. production 전체 Discord raw payload logging은 정적 검사로 막았다. 향후 Diagnostic ZIP은 allowlist만 허용하며 실제 exporter는 M8.2다.

## 7. Lifecycle / Release Compatibility

Shutdown은 여러 요청이 겹쳐도 한 번만 정리되며 auxiliary window close/HUD hide는 종료 요청이 아니다. borrowed `HwndSource`는 hook만 제거하고 dispose/destroy하지 않는다. Settings single instance와 event lifecycle은 기존 검증을 유지한다.

정적 감사에서 single-file에 위험한 assembly location/working-directory/development absolute-path 의존은 발견되지 않았다. runtime user data는 `%LOCALAPPDATA%\GachaOverlay` 아래에 있고 번들 asset은 WPF/embedded/content base 경로를 사용한다. 실제 publish와 설치 산출물 검증은 M8.3이다.
