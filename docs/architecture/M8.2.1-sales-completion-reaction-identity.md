# M8.2.1 Sales Completion Reaction Identity Hardening

## 1. 요약

Production 판매 완료 반응을 `SOLD` 하나에서 `SOLD OR closed`로 확장했다. 두 반응은 하나의
completion evidence로 정규화되며 Sold record는 삭제하지 않고 active queue에서만 제외한다.
두 marker가 모두 없다는 완전한 관측이 들어온 경우에만 Pending 복귀를 허용한다.

## 2. Actual UIA Reaction Identity

## 3. Completion Matcher

- `SOLD`: ID `1451583544295034940`, canonical name `SOLD`
- `closed`: ID `1418284521337651321`, canonical name `closed`
- 명시적인 ID가 있으면 ID만 비교한다.
- 명시적인 다른 ID는 canonical name이 같아도 no match다.
- ID가 없을 때만 case-sensitive canonical identifier fallback을 사용한다.
- substring match는 사용하지 않는다.
- 두 marker는 OR semantics이며 둘 다 있어도 하나의 completion state다.
- matcher와 raw UIA 문자열은 App sensor boundary에 있고 Core는 정규화된 boolean evidence만 받는다.

## 4. Sales Queue Behavior

- Sold record는 Current Seller, Waiting Queue, Queue Detail, ActiveCount, WaitingCount에서 제외된다.
- current가 Sold가 되면 기존 queue ordering으로 current/next를 다시 계산한다.
- 두 marker 중 하나만 제거되고 다른 하나가 남으면 Sold를 유지한다.
- 완전한 관측에서 둘 다 제거되면 Pending으로 돌아간다.
- 복귀 시 `CreatedAt`, numeric Snowflake 순서가 복원된다.

## 5. Sales Trust Regression

- `Sold + NotObserved`는 Sold를 유지한다.
- Partial 관측의 marker 누락은 NotSold evidence가 아니다.
- 완전하고 신뢰된 관측에서 두 marker가 모두 없을 때만 NotSold evidence를 만든다.
- UIA unavailable, 다른 channel, sensor error 동안 마지막 queue와 Sold record를 보존한다.
