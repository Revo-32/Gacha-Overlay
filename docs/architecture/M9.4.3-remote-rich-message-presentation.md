# M9.4.3 Remote Rich Message Presentation

## Scope

M9.4.3 changes only Remote chat presentation and the two Remote settings selectors.
Legacy Local RPC fallback text, Remote authentication, channel authorization, Sales, and the
transport protocol remain unchanged.

## Semantic boundary

`RemoteChatIngressAdapter` keeps wrapper content and wrapper media separate from immutable
Forward snapshots. A Forward snapshot is projected into a `ChatForwardPresentation`; it is not
flattened into primary text, attachments, embeds, or stickers. Structured Remote Sticker and
Forward data therefore take precedence over opaque legacy fallback kinds.

A Discord message reference is user-visible Reply context unless its reference kind is
`Forward`. A `Forward` reference is source linkage for the Forward snapshot and is not rendered
as Reply context.

## Deterministic composition order

The normal and compact HUD layouts render every Remote message in this order:

1. Author and optional timestamp
2. User-visible Reply context
3. Non-empty wrapper text
4. One structured Forward block per snapshot
5. Wrapper Sticker and direct image media
6. Direct voice/file attachment details
7. Direct embed details
8. Poll details
9. Read-only component details

Each Forward block renders its label, non-empty text, Sticker, attachment/embed image, and other
attachment/embed/component details in that order. Forward snapshots do not display an original
author because Discord does not provide one.

## Media and failure policy

Sticker format names are mapped to the existing numeric Sticker format policy. PNG, APNG, and
GIF use the existing bounded Sticker cache; Lottie and unsupported formats retain a localized
`Sticker: <name>` fallback. Forward images use the existing bounded thumbnail cache. A failed
Forward image keeps a localized attachment identity inside the Forward block.

No Backend media proxy, new downloader, new cache, polling loop, or production Discord test is
introduced.

## Settings selectors

The shared ComboBox control template renders the selected item through `ItemTemplate`, so the
Remote source and channel selectors use an explicit `DisplayName` template. Channel labels are
shown as human-readable `#channel-name` values rather than record `ToString()` output or raw IDs.
