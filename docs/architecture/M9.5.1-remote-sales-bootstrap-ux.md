# M9.5.1 Remote Sales bootstrap UX arbitration

M9.5.1 changes presentation ownership only. It does not change
`SalesStateEngine`, completion-marker matching, queue ordering, or personal-alert
rules.

## Root cause

The Remote production coordinator exposed `sales_ready` and terminal Sales
failures, but it did not publish a Sales lifecycle event before the bootstrap
HTTP request. Until `sales_ready`, `SalesPresentationCoordinator` therefore used
the current UIA health directly. If Discord was displaying another channel, UIA
reported `TargetChannelNotSelected` and the HUD incorrectly asked the user to
keep the Sales channel open while Remote Sales was healthy and synchronizing.

## Effective source model

The merged presentation now uses `EffectiveSalesSource`:

- `LegacyOnly`: existing Local RPC/UIA behavior.
- `RemoteStarting`: Remote connecting or bootstrapping; UIA remediation is
  suppressed.
- `RemotePrimary`: Remote Live/Complete evidence owns the visible health.
- `RemoteRecovering`: Remote resyncing or reconnecting; UIA remediation is
  suppressed while the Remote provider is making progress.
- `UiaFallback`: Remote is terminally unavailable and UIA is explicitly the
  effective fallback; existing UIA remediation is visible.
- `Unavailable`: reserved for a Remote terminal condition without a usable
  fallback.

`RemoteSalesPresentationPhase` supplies the finer lifecycle phase used for
localized status wording. Both models are event driven; no startup grace timer
or polling loop is used.

## Evidence safety

Remote lifecycle changes request a UI refresh but do not apply an observation
batch. Existing Remote evidence and the current queue remain in memory during
starting and recovery states. Complete Remote evidence remains preferred while
Remote is Live, and the existing UIA path is unchanged in Legacy or explicit
fallback mode.

## Validation helper safety

The shared M9.4/M9.5 helper checks the loopback endpoint before Discord ID and
Bot Token prompts. If the listener is a validated, temporary helper-owned
`dotnet ... LSOverlay.Backend.dll` process, the helper writes that session's
`shutdown.request` and waits for a clean exit. It never force-stops an unknown
port owner. M9.5 state and preserved failure logs use the M95-specific temporary
directory names.

M9.6 cutover, UIA removal, and reaction write-back are not part of this change.
