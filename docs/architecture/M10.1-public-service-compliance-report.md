| 로그·진단 | 로컬 로그 기본 2MiB×최대 5개, 사용자 생성 정제 ZIP은 자동 업로드하지 않음 |

## 7. Public Status API

목표 URL: https://overlay.revo32.cloud/status/public

정확한 필드 구조 예시입니다. 아래 값은 운영 조회 결과가 아닙니다.

```json
{
  "schemaVersion": 1,
  "overall": "operational",
  "updatedAt": "2026-09-03T06:00:00+00:00",
  "services": {
    "backend": "operational",
    "discord": "operational",
    "authentication": "operational",
    "remote": "operational"
  }
}
```

상태 값은 `operational`, `degraded`, `maintenance`, `unavailable`, `unknown`입니다.
집계 우선순위는 **unavailable > maintenance > degraded > unknown > operational**입니다.
알 수 없는 항목이 하나라도 있으면 전체 정상을 주장하지 않습니다. maintenance는 예약 값이며 현재 자동 생산자/토글이 없습니다.
`updatedAt`은 UTC 스냅샷 생성 시각이지 장애 발생 시각이 아닙니다.

`Cache-Control: no-store`, `Vary: Origin`, `nosniff`를 사용합니다.
ACAO는 정확한 `https://status.revo32.cloud` 요청에만 응답하며 credentials는 허용하지 않습니다.
공개 DTO만 직렬화하고 내부 health/config 객체·이유·카운터를 노출하지 않습니다.
API HTTP 200은 스냅샷 전달 성공이며 전체 운영 정상이라는 뜻은 아닙니다.

## 8. Status Signal Sources

| 구성 요소 | 정확한 신호와 해석 |
| --- | --- |
| Backend | `IHostApplicationLifetime` started/stopping. 시작 전 unknown, 시작 후 operational, 종료 중 unavailable |
| Discord | 기존 `BackendConnectionHealth.Current.State`. Ready=operational, Connecting/Disconnected=degraded, TargetGuildUnavailable/Faulted/Stopped=unavailable, 나머지 unknown |
| Web Authentication | WebAuth 구성·서비스 존재, 인증 저장소 fault 여부, 실행 상태, 기존 Gateway 상태, 유효 세션 용량. 구성/저장소/실행 불가=unavailable, Gateway/세션 용량 저하=degraded |
| Remote | WebSocketSession/PublicationHub host 존재, 실행 상태, 저장소 fault 여부, 기존 Gateway 상태와 global connection limiter 여유. host/저장소/실행 불가=unavailable, Gateway/용량 저하=degraded |

Auth/Remote는 **로컬 준비 상태**입니다. 외부 OAuth 공급자의 실제 응답, 개별 사용자 인증 성공,
모든 채널 bootstrap, CDN, 개별 클라이언트의 인터넷·write-back 성공을 직접 관측한 상태가 아닙니다.
해당 end-to-end 측정은 UNKNOWN / DEFERRED이며 합성 로그인·자체 WebSocket·Discord probe를 추가하지 않았습니다.
세션 용량 읽기는 최대 128개를 검사하며 세션 정리나 인증 정책을 변경하지 않습니다.

## 10. Status Failure Semantics

- Backend 응답 불가: 사이트가 독립적으로 열리는 한 Backend는 이용 불가, Discord/Auth/Remote는 **상태 확인 불가**.
- Discord 재연결: 실제 Gateway 신호에 따라 degraded/unavailable; 의존 Auth/Remote는 준비 저하를 반영합니다.
- Auth 구성·저장소 불가: authentication unavailable. 세션 용량·Gateway 저하는 degraded.
- Remote host·저장소 불가: remote unavailable. 연결 용량·Gateway 저하는 degraded.
- HTTP 실패·잘못된 JSON/스키마·과대 응답·8초 초과: 깨끗한 한국어 실패 표시, 오래된 정상 색 제거,
  실패한 확인 시도 시각 표시. 원시 예외·내부 메시지는 표시하지 않습니다.
- 브라우저 인터넷/CORS 장애도 확인 실패일 수 있으므로 API 미도달을 모든 외부 서비스 장애로 단정하지 않습니다.
- 상태 사이트만 중단되면 API는 살아 있을 수 있으며, Railway 전체 장애에서는 두 서비스 모두 접근 불가할 수 있습니다.

## 11. Security / Privacy Boundary

공개 응답/문서/정적 산출물에 실제 Guild/User/Host/Channel ID, Bot Token, OAuth Client ID/Secret,
access/refresh token, ClaimSecret, Remote credential/hash, installation ID, 접속자 IP·이름,
메시지·판매 본문·Presence 신원, 파일 경로·스택·환경 변수·Railway 비밀정보를 삽입하지 않습니다.
예제 private 설정값을 넣은 HTTP/정적 자산 검사를 추가했습니다. 정책 본문의 일반적인 “토큰” 설명은 비밀값과 구별합니다.

Legal 페이지는 route 전용 CSP/nosniff/no-referrer를 적용하고 JS가 없습니다.
상태 사이트는 self-hosted 자산과 Backend HTTPS 연결만 허용하는 meta CSP를 사용합니다.
catch-all SPA, 전역 CORS 완화, 방문자 식별 로그, analytics, 쿠키, 브라우저 영구 저장소가 없습니다.
로고 source bytes는 동일하며 최종 정적 웹 루트는 명시한 네 파일만 포함합니다.

## 12. Web OAuth Regression

공식 Discord authorize, `https://overlay.revo32.cloud/auth/discord/callback`, identify-only,
PKCE S256, 독립 state/ClaimSecret, Bot Guild 검증, DPAPI credential reuse 의미를 유지했습니다.
WebAuth의 추가 코드는 읽기 전용 용량 관측뿐입니다. OAuth token 저장·WPF 전달 정책은 바꾸지 않았습니다.
healthz의 간단한 기존 응답, callback CSP, API/Remote/WebSocket 경로와 보안을 회귀 검증했습니다.
slash pairing·pairing code·UIA·Local RPC·legacy OAuth·별도 로그인 웹사이트는 다시 넣지 않았습니다.
실제 운영 로그인 재시험은 수동 배포 후 항목이며 이번 자동 검증에서 사용자 로그인은 하지 않았습니다.

## 13. Performance / Lifetime

Bot은 Ready 이벤트 기반이며 cosmetic 호출에만 2초 일회성 대기 제한이 있습니다.
Backend 공개 상태는 외부 I/O 없는 로컬 스냅샷이며 새 background service·정기 polling·DB·사용자별 상태 저장이 없습니다.
Legal HTML/CSS/로고는 lazy로 한 번 로드하여 재사용합니다. 스트림은 해제합니다.
상태 웹페이지에만 60초 예약과 요청당 8초 timeout이 있으며 pagehide에서 timer/fetch를 정리합니다.
신규 Discord/Remote 연결이나 상태용 WebSocket은 없습니다. 기존 resource lifetime과 WPF UX는 그대로입니다.

## 21. Known Limitations

- Bot 문구는 고정이며 공개 상태와 연동하지 않습니다. Bot이 “정상 가동 중”인데 API는 지연 상태일 수 있습니다.
- 현재 상태만 있고 incident/uptime 이력은 없습니다. maintenance 자동 신호도 없습니다.
- Auth/Remote는 서버 내부 readiness이지 end-to-end 보장이나 모든 사용자 상태가 아닙니다.
- Railway 전체 장애에서는 독립 서비스여도 둘 다 열리지 않을 수 있습니다.
- 공개 문의처는 확정했습니다. 실제 데이터 삭제 요청의 본인 확인·처리는 운영자가 수행해야 하며 법률 검토·인증 완료를 주장하지 않습니다.
- 실제 Docker 이미지·Linux httpd 동작·운영 배포 후 Bot/HTTPS/CORS/TLS 확인은 미실행입니다.
- 기존 M82 진단 ZIP 테스트의 중간 간헐 실패가 있었고 원인을 확정하지 않았습니다. 최종 전체 결과와 별도로 추적해야 합니다.
