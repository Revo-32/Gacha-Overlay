2026-09-14. **진행 중, 최종 parity/A-B 통과 또는 M7 배포 후보가 아님.** 공개 브랜치·버전·태그·릴리즈와 Production/Full 설정은 변경하지 않았다.

- 수정 native Release: `artifacts/core/m6-hud-polish/native/Release/LSOverlayCore.exe`. 이전 `m6`, `m6-next`, `m6-ux`, `m6-corrective`, `m6-media-ux` 실행본은 덮어쓰지 않았다. 사용자가 Core만 종료하고 스크립트를 다시 실행해야 클라이언트 수정이 반영된다.

- Production Backend/Status image, container identity, 시작 시각, health를 교체 전후 비교했고 변경 없음. 원래 OAuth issuer에 직접 로그인하며 Core 전용 DPAPI만 사용. 봇 자격증명 import/Discord 쓰기 없음.

## 실제 확인과 교정

- 사용자가 실제 연결 및 이미지/GIF 표시를 확인했고, 자체 계측에서 네이티브 프레임 진행을 확인했다. 화면에서 발견된 아래 문제 때문에 시각 동등성은 통과 처리하지 않는다.
- 판매 상세 이모지: 정사각형 칸으로 bitmap을 강제 늘리던 부분을 Uniform fitting으로 변경. 원본 종횡비를 유지하고 칸 안에서 정렬.
- 작은 GIF: 물리 원본 픽셀 수와 논리 표시 크기를 분리. Full의 큰 미리보기 기준 최대 360×270 DIP, 창 폭 내 aspect fit. 원본을 서버에서 불필요하게 업스케일하지 않으며, 필요한 물리 profile/원본 프레임 시간·반복·alpha는 유지.
- 링크: 서버가 Full의 `ChatMediaSourcePolicy`를 재사용해 첫 미리보기와 정확히 연결된 원본 URL run만 표시. 클라이언트는 첫 프레임 decode 성공 이후에만 그 run을 숨김. 다른 URL/추가 미디어 URL/아직 로딩 중이거나 실패한 미디어 URL은 보존. 숨김·재표시 때 성공 상태를 유지하고 실패 때 복구.
- 로딩: 빈 윤곽 사각형 대신 테마색 로딩 안내. bounded 압축 파일 LRU를 재사용해 화면 밖/복귀 때 중복 HTTP를 줄임. 파일/바이트/진행 중 예약을 포함한 한도를 유지하며 수신 worker 2개로 단일 느린 다운로드가 다른 미디어까지 막는 문제를 완화. UI/채팅/decoder thread에서는 다운로드하지 않음.
- 숨김/retain: 같은 derivative를 공유하는 다른 alias가 남아 있는데 이전 alias 삭제가 visible 상태를 잘못 지우던 문제 교정. 비표시 buffer와 lease는 해제하고 압축 캐시는 byte LRU가 관리.
- bootstrap 중 staged Chat mutation이 ready cursor보다 오래된 것으로 거부되던 SDK 문제는 기존 Sales와 같은 원래 bootstrap cursor + 순차 replay로 교정. 0/1/3개 staging 및 후속 live mutation 회귀 추가. Full 인입 동작 집중 회귀 통과.
- Chat/Sales bootstrap이 서로의 media 권한 scope까지 지우지 않도록 채널 단위 revoke. 삭제/권한 철회 및 변환 전후 권한 재검사는 유지.
