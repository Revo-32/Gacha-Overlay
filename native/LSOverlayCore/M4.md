# Core M4 — 서버 보조 미디어 경로

상태: **CONDITIONAL PASS — 구현/합성 검증 단계**. 실제 문제 GIF의 Full/Core A/B, 인증된 원격 미디어 전송, 모든 provider·스티커 품질 동등성을 완료했다는 뜻이 아니다. M7 공개·내부 배포 후보 판정은 아직 하지 않는다.

## 구현

- 별도 서버용 `LSOverlay.CoreMedia`: 실제 표시 픽셀 profile, source SHA-256 + profile + codec/pipeline version identity, sRGB/alpha 및 종횡비, 원본 프레임 시간·합성·반복 횟수를 보존한다. 크기가 같으면 보간하지 않아 경계 픽셀을 흐리지 않는다.
- 변환 결과는 독립된 **무손실 PNG 프레임과 시간/index/hash**를 갖는 `.lscm` 파일이다. 새로운 압축 코덱이 아니며 원본 GIF의 의존 프레임 합성 작업을 클라이언트의 매 반복마다 수행하지 않는다. PNG sequence의 실제 파일 크기/전송량은 실자료에서 추가 측정해야 한다.
- 캐시는 원본 보관소가 아니다. 원본은 임시 입력 후 제거하며 hard 1 GiB, high 900 MiB, low 768 MiB에 임시 파일도 포함한다. 단일 owner, LRU, 사용 중 lease, 원자적 publish, 고아 임시 파일 청소, symlink/외부 디렉터리 거부, bounded queue를 사용한다.
- source 64 MiB, source 67,108,864 pixels, profile 16,777,216 pixels, 10,000 frames, derivative 512 MiB로 작업 비용을 제한한다. 초과 시 품질을 낮춰 성공 처리하지 않고 실패한다. 큰 정상 자료의 지원 한도 적합성은 실측 gate에서 판단한다.
- canonical Discord CDN 소스만 fetch한다. 클라이언트가 입력한 URL을 받는 HTTP endpoint는 없다. opaque reference는 viewer/channel/message에 묶이고 조회할 때 현재 권한을 다시 확인한다. HTTPS, 정확한 host/path, DNS public-address 검증 후 실제 IP에 연결, 정상 TLS 검증, redirect/proxy/cookie/credential 및 과대 response 차단을 포함한다.
- `LSOverlay.CoreMediaWorker`는 별도 process용 one-shot CLI다. 30초 fetch/35초 job cancellation 외에 **부모 process/container의 강제 종료 기한과 memory limit가 필수**다. 요청 thread/운영 Backend에 등록하지 않았다. 아직 외부 사용자용 service가 아니다.
- native WIC PNG decode는 별도 thread에서 수행한다. 파일-backed encoded data와 현재/다음 decoded frame만 유지하고, 같은 derivative를 여러 message/emoji가 참조해도 decoder/pixel/bitmap을 공유한다.
- 인라인 이모지는 DirectWrite inline metrics로 줄바꿈/기준선을 유지한다. 이미지 역할 아이콘, custom reaction, 전달 이미지, 첫 첨부 + N 안내를 렌더링한다. 누락/실패에는 읽을 수 있는 이름을 남긴다.
- 화면 밖/숨김 시 buffer를 해제하고 decode/render를 멈춘다. 다시 보일 때 logical timeline 위치를 복구한다. FPS 제한/정책적 프레임 생략은 없다. 실제 지연으로 순서가 건너뛴 경우는 별도 counter에 남긴다.
- 정적인 글자/배경을 물리 해상도 bitmap으로 재사용한다. animation-only invalidation은 glyph outline을 다시 그리지 않는다. resize/DPI/font/상태 변경/target recreation은 정적 layer를 재구성한다.

## 검증 기록

2026-09-13 기준:

- Windows .NET 8 server media/security 집중 검증 **85 assertions PASS**. byte budget뿐 아니라 파일 개수 한도/재시작을 포함한다.
- M8 Linux에서도 **85 assertions PASS**, network `none`, non-root, read-only root, 512 MiB/0.5 CPU, 45초 parent deadline. Production ID/image/start/health 변경 없음. one-shot 테스트 컨테이너 종료/제거.
- native CTest 5/5 PASS; Windows WIC가 서버 생성 package의 가변 시간/합성/alpha를 읽는 cross-language 검사 PASS.
- native 합성 GUI: GIF + 정적 이미지 + inline/reaction emoji, hide/show, offscreen/resume, 0% 편집 테두리, font change, render target recreation **40 assertions PASS**. 직접 키/물리 모니터 검증은 기존 M1 사용자 확인과 별개이며 이번에는 Full의 단축키를 등록하지 않는다.
- 기존 M3 native text GUI 회귀 **12 assertions PASS**, 8초 idle CPU 0%/repaint 0. Linux가 만든 GIF package를 Windows WIC로 읽는 검사도 PASS.
- 같은 640×880 합성 workload의 약 3초 구간: static-layer 재사용 전 CPU **41.16%**, 후 **2.60%** (단일 코어 기준). 후 Private Bytes **16,154,624**, Working Set **38,178,816**, 현재/다음 픽셀 **603,392 bytes**, 비연속 frame counter **0**. 짧은 합성 계측이며 Full 비교/10분 안정성/KPI 최종 판정이 아니다.
- NuGet 공개 advisory 조회에서 새 SkiaSharp 3.119.1 dependency graph의 알려진 취약점 보고 없음. 기존 Full과 같은 버전이며 Full package graph는 바꾸지 않았다. Skia/third-party notices는 배포 후보의 별도 license gate 대상이다. native client에는 .NET/Skia runtime을 넣지 않았다.

상세 artifact는 ignored `artifacts/core/m4/`에 있다. 실제 Discord 내용/자격증명은 이 합성 fixture에 없다.

## 남은 gate

실제 인증된 Backend/미디어 reference와 transport 연결, 더 큰 표시 profile 재요청/확대 UX, source URL 숨김 설정 동등성, Discord 외 provider와 모든 sticker format, EXIF/ICC 추가 reference 비교, 실제 문제 대형 GIF와 Full 동일 workload A/B가 남았다. 현재 local manifest는 명시적인 개발 fixture seam이며 제품용 media API나 실시간 로그인으로 표현하지 않는다.
